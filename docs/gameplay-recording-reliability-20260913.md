# 게임플레이 기록 누락 방지 개선

테스트 빌드: `0.6.70-test.20260913.2` (Windows x64, 자체 포함 실행 파일, 자동 업데이트 차단)

## 변경 사항

- 현재 스캔의 실제 라운드만 기록한다. 라운드를 읽지 못했을 때 UI의 이전 라운드로 대체하지 않는다.
- 라운드 미확인 관측과 인식 공백을 동의 기반 로컬 복구 자료로 보존한다. 가짜 라운드나 조합 이벤트로 서버에 보내지 않는다.
- 조합·선위 판별은 인벤토리와 위습의 전체 수량 변화를 대조한다. 여러 행동이 겹쳐도 해석이 유일하고 정확히 일치할 때만 각각 기록한다.
- 최대 8개 기준 관측을 보존하여 자원·라운드 갱신이나 지연된 출력이 기존 조합 근거를 지우지 않게 한다.
- 모호한 변화, 설명되지 않는 증감, 미확인 유닛, 랜덤 위습, 탐색 한도 초과는 행동으로 추정하지 않는다. 원래 관측은 별도로 유지한다.
- 관측마다 디스크에 부분 패킷을 체크포인트한다. 디스크 저장 작업과 HTTP 작업을 분리해 느린 서버가 저장을 막지 않게 한다.
- 부분 패킷은 전송하지 않는다. 봉인된 패킷의 ID와 내용은 고정하며, 정확히 일치하는 접수 응답을 확인한 파일만 삭제한다.
- 재시작 시 유효한 부분 패킷과 완전히 기록된 임시 파일을 복구한다. 불완전한 임시 파일은 기존 정상 기록을 유지한 채 정리하고 오류를 표시한다.
- 대기열이 가득 차도 기존 미접수 패킷을 밀어내지 않는다. 저장 중단을 표시하고 새 관측을 로컬 복구 자료에 남긴다.
- 저장 중단 때문에 실제 관측이 빠진 구간을 완전한 클리어 학습 기록으로 위장하지 않는다. 이전 기록 조각은 interrupted로 종료하고 다음 확인된 상태부터 새 조각을 시작한다. 실제 게임 결과의 기존 v2 집계와는 별도다.
- 종료 시 서버 전송으로 공간이 생기면 메모리에 남은 패킷의 디스크 저장을 다시 시도한다. 그래도 저장하지 못한 봉인 패킷은 별도 복구 공간에 정확한 원본 바이트로 보존한다.
- 다음 실행 또는 주기적 처리에서 해당 봉인 패킷을 정규 대기열로 되돌린다. 로컬 관측·공백 자료 자체는 자동 업로드하지 않는다.
- 저장 중단, 오류 이력, 만료 및 복구 자료 상태를 메인 창 하단에 표시한다. 종료 시 복구 저장까지 실패하면 경고한다.

## 저장 위치와 한도

기준 폴더: `%LOCALAPPDATA%\OrandOverlay\gameplay-v3`

| 위치 | 용도 | 한도 |
| --- | --- | --- |
| `pending\*.draft.json` | 아직 봉인되지 않은 부분 패킷 | 정규 대기열과 합산 |
| `pending\*.v3.json` | 서버 접수 대기 중인 봉인 패킷 | 256개, 32 MiB |
| `recovery\*.recovery.json` | 라운드 미확인 관측·인식 공백 | 복구 공간 전체 512개, 32 MiB |
| `recovery\*.packet.recovery.json` | 종료 시 정규 대기열에 저장하지 못한 봉인 패킷 | 같은 복구 한도 내 4개 슬롯·2 MiB 예약 |

- 보관 기간은 30일이다. 보관 만료는 무제한 보존과 다르다.
- 임시 파일도 저장 한도 계산에 포함한다. 이름이 다른 사용자 파일을 임의 삭제하지 않는다.
- 공간 부족 시 최신 관측을 무한히 메모리에 쌓거나 오래된 미접수 자료를 조용히 삭제하지 않는다.
- 설정·로그·사용자 데이터는 배포 ZIP에 포함하지 않는다.

## 동의와 호환성

- 기존 최초 명시적 동의 정책과 fixture의 외부 효과 차단을 유지한다.
- 외부에서 동의 설정 파일을 변경하면 다음 권한 검사에서 반영된다. 이미 시작된 I/O를 소급 취소한다고 보장하지 않는다.
- 서버 schema 3의 이벤트 종류·필드·엄격한 ACK 규칙은 변경하지 않았다. 이번 개선을 위해 서버 배포를 수행하지 않았다.
- 추천을 실제 실행으로 간주하지 않는다. 게임 입력 자동화, 메모리 쓰기, DLL 인젝션을 추가하지 않았다.
- 신규 TMO 수집, `unitCount=0` 의미 변경, `MemoryDiagnostics` 수정은 하지 않았다.

## 검증과 남은 한계

- 관련 앱 회귀 테스트: 853개 통과.
- 기존 Worker/학습 계약 테스트: 18개 통과.
- Python 수집기 테스트: 27개 통과.
- 모의 HTTP로 느린 전송 중 체크포인트, 대기열 포화 후 복구, 종료 후 원본 바이트 재전송, 중복·잘못된 ACK, 동의 변경 및 임시 파일 복구를 검증했다.
- 단일 실행 파일의 런타임 포함, 테스트 빌드 식별, 패 수치 데이터 일치, 개인 설정·로그 제외를 검증한다.

읽기 전용 주기적 관측이므로 인식 사이에 발생한 모든 실제 클릭이나 행동을 100% 확정할 수는 없다. 물리적 디스크 오류, 모든 저장 공간 소진, 저장 완료 전 강제 종료도 완전 보장 대상이 아니다. 확인할 수 없는 정보를 만들어 채우는 대신 가능한 관측과 복구 자료를 보존한다.

실제 동의된 게임 클리어 1건의 운영 서버 영속 저장은 별도 확인이 필요하다. OPTIONS 허용 응답이나 모의 테스트 통과만으로 운영 DB 저장 완료라고 판단하지 않는다.
