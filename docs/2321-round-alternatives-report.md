# ORDR 2.321 라운드 인식: 메모리 직접 읽기 외 대안 분석

- 작성일: 2026-09-16
- 범위: 방법론 분석·보고. 코드 수정, 게임 실행, 저장 캡처 재검사 없음.

## 결론

- "직접 게임을 실행해 메모리를 읽는 방법"만 있는 것은 아니다.
- 추천 조합: **맵 JASS 정적 분석(라운드 규칙 확정) + 녹화 영상/스크린샷 OCR(실측 표시값 검증)**.
- 이 두 단계는 기존 2.321 녹화 자료만 있으면 게임 실행 없이 진행 가능.
- 유일하게 대체 불가한 것: **현재 메모리 판독기의 주소·값 정합성 증명**. 이는 해당 실행에서 나온 메모리 증거가 필요하다.
- 랜디픽의 제품 목적이 "현재 라운드 표시"라면 메모리 방식에 의존할 필요가 없다.

## 방법 비교

| 방법 | 게임 실행 없이 분석 | 확인 가능한 것 | 주요 한계 | 우선순위 |
|---|---|---|---|---|
| 맵 JASS 정적 분석 | 가능(맵 파일 이미 보유) | 라운드 변수 의미, 변경 조건, 표시 규칙, 2.320/2.321 동작 차이 | 특정 판의 현재 값은 모름 | 높음 |
| 녹화·스크린샷 OCR | 자료가 있으면 가능 | 화면에 표시된 실제 라운드 | 가림, 해상도, 오인식. 화면에 없는 정보 불가 | 높음 |
| 리플레이(.w3g) 파싱 | 파일이 있으면 가능 | 게임 버전, 입력, 채팅, 사용자 정의 기록 | JASS 변수 시계열이 바로 나오지 않음 | 중간(존재 조사 후 확대) |
| 맵 제작자 협력/W3MMD | 기록 자료가 있으면 가능 | 맵이 명시적으로 내보낸 라운드 데이터 | 제작자 협력 또는 기존 출력 필요 | 장기적으로 높음 |
| 기존 메모리 덤프 재판독 | 충분한 덤프가 있으면 가능 | 캡처 시점 내부 값·구조 반복 분석 | 최초 메모리 수집을 없애지는 못함 | 조건부 |
| JASS 부분 실행 | 가능 | 로직 전이·경계 조건 검증 | 실제 엔진 동작과 동등성 미보장 | 보조 |
| 수동 라운드 입력 | 구현·테스트 가능 | 사용자가 확인한 값 | 자동 인식 아님 | 안전한 보조 |

## 핵심 내용

1. **맵 정적 분석**: `Ag/lg/yp/Vu`를 이름이 아닌 "사용되는 방식"으로 검증. 초기화, 모든 변경 지점, 호출 트리거, 제목 생성, 시작 전/보스/종료/재시작 분기 추적. 결과는 2.320 대비 단순 이름 변경인지 동작 변경인지 판정에 재사용. 한계: 규칙이지 특정 실행 상태가 아님.
2. **OCR**: 창/디스플레이 프레임 획득은 공식 `Windows.Graphics.Capture` API로 가능. 개발·검증은 저장 영상으로, 이후 실시간은 같은 판독기에 창 캡처 전달. 정확도 평가는 사람이 붙인 정답 라벨 대조: 전환 직전·직후, 시작 전 안내 구분, 해상도/UI 배율/압축 차이, 가림, 실패 시 "미확인" 처리와 마지막 관측값 경과 시간 표시.
3. **리플레이 파싱**: 공개 파서(w3gjs 등)가 헤더·게임 데이터 블록을 해석. 단, 파싱은 상태 재현이 아니고, 공개 파서의 3.0·2.321 지원은 미확인. 라운드 관련 기록 존재 여부를 먼저 짧게 조사.
4. **제작자 협력/W3MMD**: 맵이 JASS 라이브러리로 리플레이에 사용자 정의 데이터·이벤트를 기록하는 표준 방식이 존재. 라운드 변경 이벤트 기록이 장기적으로 가장 명확. 실시간 전달 경로는 별도 검토 필요. 2.321 포함 여부는 미확인. 원본 맵 임의 수정 배포는 비추천.
5. **덤프**: `MiniDumpWithFullMemory`는 접근 가능한 전체 메모리 포함(일반 미니덤프와 다름). 반복 실행을 줄이는 도구일 뿐 수집 자체를 대체하지 않음. 개인정보·용량 주의. 기존 목록 JSON은 대체물이 아님.
6. **JASS 부분 실행**: 라운드 로직만 분리해 경계 조건 검증. Warsmash 같은 재현 프로젝트도 "일부 동작" 수준. 전체 맵 재현은 라운드 인식보다 큰 작업.
7. **시간 경과 추정**: 구현은 쉽지만 오차 누적. 추정값은 관측값으로 표시 금지.

## 진행 순서(제안)

1. 맵 파일만으로 라운드 규칙 확정(오프라인).
2. 기존 2.321 녹화/스크린샷으로 OCR 정확도 검증(오프라인). 여기까지 게임 실행 불필요.
3. 리플레이에 라운드 이벤트/W3MMD 기록 존재 여부 조사. 없으면 엔진 재현으로 확대하지 않음.
4. 랜디픽 입력 출처 분리: `화면 인식` / `수동 입력` / `메모리 진단`을 별도 출처로 유지.

## 미확인 사항

- ORDR 2.321에 W3MMD 또는 동등한 라운드 출력이 존재하는지 여부.
- 공개 리플레이 파서의 3.0(Reforged)·2.321 리플레이 지원 여부.
- OCR 정확도 수치(정답 라벨 자료 확보 후 측정).
