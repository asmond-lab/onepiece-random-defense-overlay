# ORDR 2.320 변경 검토

> **최신 상태: 원본 추출·구문 검사·오브젝트 전수 비교와 핵심 변경 분석 완료.** 이전의 추출 불가 상태는 해결됐다. [최종 분석 보고서와 상세 근거](analysis-2320/README.md)를 우선 참조한다. 아래 공지/영향 표는 초기 패치노트 기준이며 실제 소스와의 차이는 최종 보고서에 분리했다. 운영 데이터·Warcraft 3.0 승인·배포는 여전히 변경하지 않았다.

## 확인한 원본

- 사용자 지정 맵: `ORDR_S2_2.320[R].w3x`
- 로컬 파일: `C:\Users\123\Documents\Warcraft III\Maps\Download\ORDR_S2_2.320[R].w3x`
- 119,129,261 bytes, SHA-256 `68445631FDACA12A343E9465E5BC5DC9B4C8C6CC927D701F52E2CB822821E15F`
- 이전 2.314: 134,758,580 bytes, SHA-256 `F9DDD3AF7C0FBFD39B7A6DF2CA0F5F295675BBA5E8B91A5322DCEC93D7CA8A83`. 기존 번들 메타데이터와 일치한다.
- 패치노트: [ORDR 커뮤니티 디스코드, ORDR 2.320 패치노트](https://discord.com/channels/1274561926088757268/1464613431499034750/threads/1548597846377504828), 2026-09-13 16:34 게시. 사용자가 열어 둔 스레드의 본문을 직접 확인했다.
- 디스코드 본문 근거는 `analysis-2320/patchnotes/`에 보존했다. TMO 신규 수집은 하지 않는다.

## 운영에 중요한 공지

개발자는 리포지드 업데이트 버그 때문에 긴급 출시했고 신규 기능 테스트가 부족할 수 있다고 안내했다.

- 2.314 이하 클래식 맵의 로드/세이브는 9월 14일 23시까지라고 공지했다.
- 2.314 이하의 TMO 정식맵 인식도 같은 기한이다. 2.320 수정맵 구분 및 클리어 기록 저장은 TMO 프로그램 업데이트가 필요하다고 안내했다. 이는 랜디픽 서버의 저장 성공 증거가 아니다.
- 리포지드에서 F11 재화 전송 시 비정상 종료 문제가 있어 해당 전송을 막고, 상대 유닛을 선택한 상태의 `-골드 xx`, `-목재 xx` 임시 명령을 추가했다. 검증 도구는 이 명령이나 다른 게임 입력을 실행하지 않는다.

## 패 수치와 조건부 효과 대조 대상

- 미나토: 발동13.5%, 범위600, 스턴3초. 시키: 단일 스턴1.25초, 저항무시.
- 사토루: 아오 이감 삭제, 아카에 이감 추가. 수치/조건을 합쳐 상시 이감으로 처리하지 않는다.
- 키드: 시전시간 추가와 스턴2.2초/2.85초×2, 데미지 변경. 베가펑크: 범위575, 스턴2.75초. 요크: 스턴3.75초 및 작동 버그 수정.
- 카이도: 특성강화 추가, 주변 아군 공격력 감소75%→45%.
- 가반: 스킬명 변경, 고정→물리 피해 및 추가발동80% 물리 피해 변경. 이름만으로 rawcode/스킬 매칭하지 않는다.
- 빅맘 특강: 스택 증가확률100%, 두 스택 비례 계수1%/0.5%.
- 니카: 패치노트는 재료 초월의 특강 조건을 안내한다. 후속 원본 분석에서 실제 플레이어 강화 플래그 조건, 대체 재료, 니카 제작 완료 플래그와 에메트/오로성 억제·복원 경로까지 확인했다. 정확한 소비 유닛 핸들의 강화 검사나 기존 적 전체의 즉시 복원으로 과장하지 않는다. 상세는 최종 분석 보고서 참조.
- 테조로: 특정 대상 추가 고정40만, 잃은체력 비례 적용 대상 변경, 저골드 효율 공식 변경. 전체 공식은 패치노트만으로 생성하지 않는다.
- 에넬 제한: 발동 이감은 특강 이후에만 적용. 구 일반/특강 합산 금지.
- 세라핌 공통 단일 스턴1.8초. 베어 여진30%, 마법 증폭3%.
- 핸콕 전설 공격시 추가 물리5만 삭제. 샹크스 전설 스턴 버그 수정. 루피 나이트메어의 보스/광폭화 전체 체력 비례 추가 피해2%.
- 네즈코·뱌쿠야·히그마·유카리·징베 등의 피해/주기/적용 대상 변경, 코비 분신 능력치/업그레이드 영향도 대조 대상이다.
- TMO 48784 수치는 기존 관측 원본으로 보존한다. 패치노트와 다른 출처를 조용히 섞거나 전 항목을 2.320 검증값으로 재표시하지 않는다.

## 반영 상태

현재 번들 데이터와 검증기는 **2.314 기준**이다. 정상적인 로컬 아카이브 API로 새 맵의 멤버/스크립트 대조를 완료했고, 후속 반영은 검증된 근거를 사용해 데이터·하드코딩된 검증기·테스트를 함께 갱신해야 한다. 오프라인 분석 완료는 2.320 운영 지원 승인이 아니다.

Warcraft III `3.0.0.24268` 실행 파일의 로컬 identity/보조 리더 미검증 문제는 별개다. 맵 파일 확인이나 오프라인 회귀 통과만으로 실행 파일 지원 프로필을 활성화하지 않는다. 원격 프로필/앱 채널과 기존 `.3` 배포물은 변경하지 않았다.

## 초기 읽기 실패와 후속 해결

- 초기 접근 정책 차단은 사용자 승인으로 해결됐고, 구 native 도구는 2.320 첫 JASS 조회에서 `0xC0000005`로 종료됐다. 같은 도구로 2.314 대조군은 정상 추출됐다.
- War3Net.IO.Mpq 6.0.3은 같은 이름의 범위 밖 해시 참조를 `FileExists → AddFileName → BlockTable`에서 역참조해 예외가 발생했다. 이 실패는 압축 해제 이전 단계였다.
- 후속 정상 StormLib API는 유효한 참조를 읽었다. 중립 locale의88-byte JASS 대신 `SFileSetLocale(1042)`로 실제 한국어 JASS 3,014,709 bytes를 추출했다. 헤더 수정·복구 플래그·대체 키는 쓰지 않았다.
- 두 버전 각각 JASS/W3U/W3A/WTS/Misc/W3T/W3Q/W3I 8개를 추출·재해시했다. 원본 맵 해시는 전후 동일하다. 새 스크립트 함수2,650개, 구2,694개 모두 전체 구문 검사를 통과했다.
- 상세 원인·정확한 도구 출처·추출물·완전한 오브젝트 diff·기능별 코드 근거는 `analysis-2320/`에 보존했다. 36개 독립 검증과 불릿 수식35사례도 통과했다. 이 결과는 앱 회귀나 실전 지원 승인으로 재표시하지 않는다.
