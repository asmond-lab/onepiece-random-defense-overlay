# 원랜디 네 모드 안내

## 모드

| 모드 | 목표 정책 | 표시 |
|---|---|---|
| 초보자 | 악몽 1상위 기록과 제어 지원 정책을 기반으로 자동 결정 | 조작·이유·완료 확인·다음 관문을 자세히 표시 |
| 일반 | 초보자와 동일 | 같은 행동을 간결하게 표시 |
| 대깨 | 1 · 더글라스 불릿 | 사용자 원문·2.314 맵 근거의 순서와 실제 보유/강화 상태 |
| 매뉴얼 | 사용자가 서로 다른 상위를 최대 두 개 지정 | 공동 재료, 목표별 진척도, 항법 제한을 함께 표시 |

초보자와 일반 사이 전환은 목표·진행·완료 확인 상태를 초기화하지 않는다.
자동 모드로 복귀할 때 이미 보유한 상위는 새로운 목표로 교체하지 않는다.
가반처럼 제어 생략 운영이 포함된 상위는 신규 초보자 자동 후보에서 제외하지만,
매뉴얼 선택과 이미 보유한 기물의 유지에는 사용할 수 있다.

## 항법

모든 모드의 항법 추천은 자동이다. 현재 패, 목표 묶음, 재료 진척도와 항법별 상위 수 제한을 반영한다.
두 목표가 있으면 0·1상위 제한 항법은 추천 후보에서 제외한다.
강한 우세 근거가 없을 때는 그 사실을 밝힌 잠정 추천을 표시한다.

`자동 평가`와 `게임에서 선택한 항법`은 별도 상태다. 사용자가 게임에서 선택 완료를
확인하더라도 자동 평가는 계속된다. 단, 21~23라 선택 구간이 끝난 뒤의 평가는 참고용이며
게임 내 항법을 바꿀 수 있다고 주장하지 않는다.

늦게 항법을 확인할 때의 목록은 실제 게임 상태를 신고하는 입력이다.
수동 추천 모드나 항법 효과를 임의로 적용하는 설정이 아니다.

## 매뉴얼 두 목표

- 같은 유닛·공유 폼을 두 목표로 지정할 수 없다.
- 재료 한 장을 두 목표에 중복 배정하지 않는다.
- 선택 목표가 이미 완성됐으면 한 기를 예약해 다른 조합의 재료로 소모하지 않는다.
- 첫 목표가 완성되면 남은 목표를 진행하며, 두 목표 완성 후에는 부족한 지원 수치를 보완한다.
- 이미 확정한 항법과 목표 수가 충돌하면 두 선택을 유지한 채 제약을 표시한다.
  현재 항법의 허용 수를 넘기는 새 상위 제작은 안내하지 않는다.

## 대깨 공략

`1 · 더글라스 불릿`을 메인/오버레이의 같은 공략 목록에서 선택한다.
등록된 원문은 솔로 악몽 운영이며 선택 난이도와 플레이어 수를 혼동하지 않는다.
소스 순서·50라 조합·보유 오라 잠재치·맵 강화 등급을 안내하고 실제 항법 확인은 별도로 받는다.
전체 전사: [공략 원문](bullet-guide-1-source.md).
조건별 구현/부분 구현/구체적인 읽기 연결 공백: [맵 근거 대조표](bullet-guide-1-map-coverage.md).
미등록 번호는 기존처럼 실행 안내를 만들지 않는다. 일반/초보자/매뉴얼의 목표 정책은 바꾸지 않는다.

## 로컬 복기와 검증 범위

패·추천·관측 변화·결과는 `coach-replays`의 로컬 JSONL에 저장된다.
원격 익명 집계에 합치지 않으며, 보유 증가를 실제 키 입력 수행으로 단정하지 않는다.

재현 명령:

```powershell
dotnet test OrandOverlay.Tests/OrandOverlay.Tests.csproj
dotnet run --project tools/PlannerEvidenceCapture/PlannerEvidenceCapture.csproj --configuration Release -- --output artifacts/four-modes --build-sha 6a09688 --four-modes
```

WPF 검증은 실제 앱의 스캔·파이프라인·모드 전환을 제어된 관측 입력으로 실행한다.
실제 워크래프트 전투 리플레이, 초보자 실전 클리어율, 골드·목재·보스 체력의 네이티브
관측 검증을 대신하지 않는다. 확인되지 않은 신호는 미확인으로 유지한다.

검증 결과: 전체 Debug 테스트 766개 통과, 실패·건너뜀 0개.
Release 빌드 경고·오류 0개. 네 모드 앱 시나리오 13개 및 100/125/150% 화면 검증 통과.
기존 가반 조합 회귀도 6개 상태에서 통과했다.
