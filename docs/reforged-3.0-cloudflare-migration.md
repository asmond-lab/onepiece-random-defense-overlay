# 리포지드 3.0 대응과 Cloudflare 업데이트 전환

## 현재 확인된 상태

- 설치된 Warcraft III: `3.0.0.24268`, x64.
- 실행 파일 SHA-256: `BD2A0DC256289DE45287BB60F3725B88F1235216D5177984377FE1CA22840A12`.
- 기존 검증 프로필: `2.0.4.23745`, revision 5.
- 새 바이너리에 CUnit RTTI는 남아 있지만 기존 로컬 플레이어 XOR 상수는 발견되지 않았다.
- 유닛 풀뿐 아니라 로컬 플레이어, 핸들 테이블, 라운드, 자원, 도박·특성·전투 보조 리더에도 구버전 종속 값이 있다.
- 새 구조를 검증하지 않은 채 버전 문자열이나 verified 플래그만 바꾸지 않았다. 현재 3.0 실전 인식 지원은 미완료다.

## 이번 후보판

`0.6.70-test.20260913.3`

- 미지원 게임도 실제 파일 버전과 EXE 해시를 진단에 남긴다. 메모리 읽기 승인 조건은 유지한다.
- 메인 창의 **호환성 복사**로 버전·해시·프로필·상태만 공유할 수 있다. 개인 경로, 메모리 주소, 플레이어 정보는 제외한다.
- 오래된 사용자 프로필 캐시가 새 번들의 빌드·리비전을 가리지 않게 병합한다. 손상된 사용자 캐시는 보존하고 유효한 번들로 대체한다.
- 미지원·미검증 상태에서 서명된 프로필 갱신을 다시 요청한다. 자동 재요청은 5분 간격으로 제한한다.
- 일반 프로필 확인은 6시간 간격이며 Cloudflare 전용 확인 시각을 사용한다. 이전 공급자의 확인 기록으로 최초 갱신이 차단되지 않는다.
- 이전 게임플레이 기록 누락 방지·복구 변경을 유지한다.

## 실제 Cloudflare 구성

- Worker: `https://orand-updates.epic42121.workers.dev`
- 비공개 R2 버킷: `orand-overlay-releases`
- R2의 r2.dev 직접 공개 접근은 비활성화했다.
- 기존 텔레메트리 Worker 및 다른 R2 버킷은 변경하지 않았다.

| 용도 | 경로 |
| --- | --- |
| 공식 앱 manifest | `/v1/channels/stable/win-x64` |
| 테스트 앱 manifest | `/v1/channels/test/win-x64` |
| 검증된 인식 프로필 manifest | `/v1/profiles/win-x64` |
| 버전별 EXE | `/downloads/{version}/OrandOverlay.exe` |
| 버전별 인식 프로필 | `/profiles/{version}/memory-profiles.json` |

Worker는 GET/HEAD만 지원한다. 쓰기·파일 목록·관리 API를 공개하지 않는다. 새 서명된 공식판을 승인하기 전에는 공식 채널을 비워 둔다.

## 업데이트 보안과 실행 정책

1. 앱에 내장된 공개키로 ECDSA P-256 / SHA-256 / P1363 서명을 검증한다.
2. 서명된 정보의 채널·버전·플랫폼·파일 경로·크기를 검증한다.
3. EXE를 내려받은 뒤 실제 길이와 SHA-256을 검증한다.
4. 설치 직전에 원본 서명과 UpdateInfo를 다시 대조한다.
5. 현재 프로세스가 끝나면 같은 볼륨에서 File.Replace로 교체하고 `.previous` 백업을 남긴다.
6. 프로세스를 시작하는 단계에서 즉시 실패하면 이전 EXE를 복원한다.

- 임의 외부 URL과 다른 origin으로의 리다이렉트를 허용하지 않는다.
- GitHub API/리다이렉트/unsigned JSON을 런타임 업데이트 경로로 쓰지 않는다.
- 프로필도 서명과 파일 해시 검증을 거친 뒤 기존 구조 검증을 통과해야 한다.
- 프로필의 서명 버전이 낮아지거나 같은 버전의 내용이 바뀌면 적용하지 않는다.
- 정상 앱은 시작 시 및 15분 간격으로 공식 업데이트를 확인한다. 기존 실전 중 자동 교체 보류 정책을 유지한다.
- 테스트 앱의 자동 교체 차단은 유지한다. 테스트 채널을 공식 채널로 착각해 설치하지 않는다.
- 현재 롤백은 **즉시 실행 실패**에 한정된다. 실행 후 장시간 정상 동작을 확인하는 health-ack 롤백은 아직 구현하지 않았다.
- 설정과 플레이 기록은 `%LOCALAPPDATA%\OrandOverlay`에 남으며 EXE 교체 대상이 아니다.

## 공식판으로 전환하는 권장 순서

1. 실제 3.0 원랜디 세션에서 유닛·소유자·라운드·보조 리더를 각각 검증한다.
2. 스모크/회귀 검증을 마친 소스를 새 공식 숫자 버전으로 다시 빌드한다. 현재 기준으로 `0.6.71`을 권장하되 기존 공식 배포 번호보다 높아야 한다.
3. 기존 테스트 EXE를 이름만 바꿔 공식판으로 올리지 않는다. 게시 도구가 실행 파일의 실제 제품 버전과 채널을 확인한다.
4. 최초 `.1/.2/.3` 테스트 사용자에게는 새 공식 EXE를 한 번 수동 교체하도록 안내한다. 이미 배포된 테스트판의 차단 코드를 서버에서 소급 변경할 수는 없다.
5. 이후 공식 사용자는 Cloudflare 공식 채널로 자동 업데이트한다.
6. 앱 변경이 필요 없는 검증된 게임 인식 수정은 프로필 채널로 별도 배포한다. C#에 고정된 보조 리더 구조가 달라진 경우에는 앱 업데이트도 필요하다.

## 게시 도구와 키 관리

- 서버 코드: `ops/update-service`
- 서명 도구: `ops/update-publisher/New-SignedManifest.ps1`
- 공개 검증 키: `Data/update-trust.json`, 앱 리소스에 내장.
- 개인 서명 키: 게시자 PC의 `%LOCALAPPDATA%\OrandOverlayPublisher\keys`, Windows CurrentUser DPAPI로 암호화.
- 개인 키는 EXE, R2, Worker, 소스 저장소 및 사용자 배포 ZIP에 넣지 않는다.
- 키 백업·복구와 향후 CI 이전은 별도로 관리해야 한다. 현재 DPAPI 파일은 다른 Windows 계정/PC에서 그대로 복호화할 수 없다.
- 게시 순서는 **새 버전의 불변 파일 업로드 → 다운로드·서명·해시 확인 → 채널 manifest 업로드**다. 기존 버전 파일을 덮어쓰지 않는다.
